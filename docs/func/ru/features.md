# Функциональные возможности

В документе описаны основные функциональные области системы. Краткий
обзор приведён в корневом `README.md`.

---

## Задания и режимы

Задание (Job) — единица конфигурации бекапа; хранится в `lentovodec.toml`
в секции `[[jobs]]`:

| Поле | Тип | Описание |
|---|---|---|
| `Name` | string | Уникальное имя задания; ключ в конфиге |
| `Description` | string | Человекочитаемое описание |
| `Mode` | string | `append` или `mirror` |
| `Paths` | []string | Корни для бекапа (файлы или каталоги) |
| `Exclude` | []string | Glob-шаблоны исключений |
| `span_depth` | int | Глубина группировки spanning-частей по каталогам; 0 (дефолт) — резка по файлам |

Режимы:

| Режим | Семантика |
|---|---|
| `append` | Бекапятся новые и изменённые файлы; удаления не отслеживаются. Каждая сессия добавляет новые версии файлов. |
| `mirror` | Дополнительно к `append` фиксируются tombstone'ы (записи об удалении). Восстановление может реконструировать зеркало каталога **на момент любой сессии**. |

### Exclude-шаблоны

- Поддерживаются шаблоны `path.Match` (одиночный сегмент) и
  `doublestar`-стиль `/**/` для рекурсивных матчей.
- Примеры: `*.tmp`, `node_modules`, `.git/**`, `**/.DS_Store`.
- Шаблон без `/` матчит базовое имя — `node_modules` отсекает такие
  каталоги на любой глубине.
- Матчинг выполняется по полному нормализованному пути, регистрозависим.
- Матч каталога-предка отсекает всё поддерево.

Управление заданиями — `lentovodec jobs list/add/remove` (см.
[cli.md](cli.md)); Web UI — экран Jobs (редактирование реализовано как
remove+add).

### Браузер путей в Web UI

В формах задания и восстановления Web UI есть кнопка «Обзор». Она открывает
серверный файловый браузер с хлебными крошками, переходом вверх, локальным
поиском и переключателем показа скрытых элементов. В форме задания можно
выбрать несколько корней, в форме `restore --dest` — один каталог. Ручной
ввод путей остаётся доступен. Браузер только читает листинг: он не создаёт,
не удаляет и не переименовывает файлы.

## Сессии и инкрементальность

Сессия — один запуск бекапа, записанный на кассету. На одной кассете
несколько сессий, нумерация с 1; первая сессия кассеты всегда FULL.

- Состояния файлов вычисляются сравнением текущего снимка ФС со снимком
  последней сессии в каталоге:
  - `Added` — файл есть на ФС, в прошлой сессии не встречался;
  - `Modified` — изменились размер или mtime (xxhash64 считается только
    для файлов, попавших в сессию);
  - `Deleted` — был в прошлой сессии, теперь отсутствует (только mirror).
- **FULL** (`--full` или первая сессия): перемотка в начало, перезапись
  цепочки с сессии 1; старые сессии очищаются из каталога. Рекомендуется
  при начале новой цепочки инкрементов.
- **INC** (по умолчанию): дозапись в конец данных (EOD).
- `--dry-run` — только сканирование и статистика, без записи на ленту.
- По завершении печатается статистика: просмотрено / добавлено /
  изменено / удалено / байт к записи.
- Если файл изменился между сканом и записью, энкодер сверяет хеш и
  завершается ошибкой, а не записывает тихо несогласованный индекс.

## Восстановление

Три режима (см. [cli.md](cli.md) для CLI-синтаксиса):

| Режим | Когда используется | Механика |
|---|---|---|
| **Full** | Аварийное восстановление всей кассеты | Сессии читаются подряд от начала; для каждой — индекс, затем tar с проверкой xxhash. Повреждённые сессии пропускаются переходом к следующей. |
| **Selective** | Выбранные файлы из конкретной сессии | Позиционирование на сессию по номеру, выбор файлов по путям и поддеревьям. Доступен в Web UI (браузер файлов сессии). |
| **Smart** | Восстановление по пути без знания сессии | Каталог возвращает все копии пути от новых к старым; при несовпадении хеша — fallback на следующую копию. Ни одной здоровой копии → `NoHealthyCopyError`. |

Общие свойства:

- xxhash64 сверяется при любом восстановлении; файл считается
  прочитанным только при совпадении хеша.
- `--dest` — восстановление в безопасный каталог (пути из индекса
  переносятся под него, имена томов вида `C:` срезаются);
  `--original` — по исходным путям из индекса (в Web UI — с
  подтверждающим диалогом о перезаписи).
- В mirror-цепочках tombstone'ы прочитанных сессий удаляют
  соответствующие файлы из целевого каталога — так реконструируется
  актуальное состояние дерева.

## Каталог

Каталог — SQLite-БД (`db` из конфига, WAL-режим) с метаданными всех
кассет, сессий и файлов:

- кассеты: UUID, имя, время форматирования;
- сессии: номер на кассете, тип (FULL/INC), время, идентификатор запуска;
- файлы: путь, размер, mtime, признак каталога, xxhash64, состояние
  (`A`/`M`/`D`).

Операции (CLI `catalog …`, REST `/api/catalog/…`, Web UI):

- списки кассет и сессий (с фильтром по кассете), файлы сессии;
- поиск по подстроке в пути;
- удаление сессии из каталога: **данные на ленте остаются**, но путь к
  ним теряется;
- prune — удаление всех сессий старше N дней;
- rebuild (CLI, локально) — реконструкция каталога с вставленной
  кассеты: в базу переносятся ярлык и JSON-индексы всех сессий.
  Сценарий DR — «утерян/порчен `lentovodec.db`», кассета, неизвестная
  каталогу, переезд на новую машину. Лента — источник истины, каталог
  — производное: **rebuild ≠ верификация**, tar-поток и хеши не
  проверяются (это работа `tape readtest`); поэтому rebuild по индексам
  быстрый. Идемпотентно: существующие сессии пропускаются, повторный
  запуск и запуск в живой каталог безопасны. Кассета с продолжением
  цепочки завершается подсказкой вставить следующую и повторить —
  данные прочитанной части уже сохранены.

Каталог переживает перезапуски (хранится на диске) и является источником
данных для smart-восстановления. Физическая порча одной копии файла на
ленте не фатальна: smart-restore возьмёт более старую здоровую копию.

## Лента и кассеты

- **Форматирование** (`tape format <name> [--force]`): перемотка,
  запись JSON-ярлыка (UUID, имя, время), двойной filemark = EOD пустой
  кассеты, регистрация в каталоге. Повторное форматирование занятой
  кассеты — только с `--force`.
- **Диагностика**: `tape readtest` читает всю кассету со сверкой хешей
  без записи на ФС (проверка носителя); `tape info` показывает ярлык.
- **Извлечение**: `tape eject` (MTOFFL).
- Выбор устройства — глобальный флаг `--device` или ключ `device` в
  TOML. Character-устройство (`/dev/nst0`) — реальный стример; обычный
  файл — эмулятор ленты `filetape` (несуществующий путь вне `/dev`
  создаётся как новая файловая лента).
- Кассеты legacy `nil-backup` (`NIL_BACKUP_TAPE`) намеренно не читаются:
  `ErrForeignFormat` с указанием магической строки. Старые данные —
  только старым бинарником, либо переформатировать с `--force`.

### Ёмкость кассеты и многотомные бекапи (spanning)

Ключи `capacity` (оценка ёмкости кассеты, для LTO-6 — `"2.2T"` с
запасом) и `min_tail` (порог остатка; дефолт — 5% capacity) в TOML
включают планировщик частей:

- **Честная ошибка до записи**: одиночный файл больше ёмкости кассеты
  (или её остатка при дозаписи) — ошибка сразу после сканирования,
  до прикосновения к ленте; файлы никогда не режутся на куски.
- **Остаток при дозаписи**: если на кассете осталось меньше `min_tail`,
  новая сессия начинается на новой кассете, а не ради пары гигабайт.
- **Многотомный бекап**: сессия, не влезающая в кассету, пишется
  частями на несколько кассет. Каждая часть — самостоятельная
  завершённая сессия (читается голым GNU tar), кассеты связывают
  указатели продолжения. В terminal-режиме смена кассеты —
  интерактивный промпт (Enter принимает предложенное имя); для
  скриптов есть флаг `--next-tape` (см. [cli.md](cli.md)). Части
  одного запуска видны в каталоге с общим идентификатором запуска.
- **Заполнение посреди части**: кассета закрывается указателем
  продолжения, часть переносится на следующую кассету целиком,
  заполненная остаётся целой для дозаписи. Две подряд не влезающие
  в целую кассету части — ошибка с рекомендацией уменьшить
  `capacity`.
- **Резка по каталогам (`span_depth`)**: per-job ключ `span_depth`
  (int, дефолт 0) заставляет планировщик резать части не по файлам,
  а по границам каталогов N-го уровня под корнем задания: «не влезло
  — вся группа откатывается к началу следующего каталога». Выгода —
  локальность: поддерево целиком на одной кассете, selective-restore
  поддерева трогает меньше кассет, содержимое кассет интуитивно
  («movies на LTO-001»). Группа целиком больше кассеты режется по
  файлам внутри (фолбэк — иначе такой каталог перестал бы
  бекапиться); заполнение кассет в среднем чуть хуже файловой резки —
  осознанный обмен.

Следование цепочке кассет при восстановлении и проверке работает
в terminal-режиме (см. ниже) и в демоне (пауза задачи на смену
кассеты — см. «Демон и фоновые задачи»).

### Восстановление по цепочке кассет

- **Полное восстановление** (`restore` без `--paths`) идёт по
  указателям продолжения: прочитав кассету с продолжением, Лентоводец
  просит «Кассета X прочитана. Вставьте кассету Y (часть N) и нажмите
  Enter:» и продолжает с сессии 1 следующей кассеты. Части пишутся
  в тот же каталог назначения по порядку.
- **Защита от «не той» кассеты**: вставленная кассета сверяется по
  имени ярлыка и обратной ссылке её первой сессии на предыдущую
  кассету; несовпадение — ошибка `ChainMismatchError` до
  восстановления данных. Вставьте верную кассету и перезапустите —
  восстановление продолжится с пропущенного.
- **Каталог не нужен**: цепочка читается с самих лент (DR-сценарий).
- **Без терминала** (cron, скрипты): восстановление завершается
  предупреждением на границе кассеты — вставьте следующую кассету
  и перезапустите команду; файлы прочитанной части уже восстановлены.
- **Проверка цепочки**: `tape readtest` следует той же логике и
  печатает отчёт по каждой кассете (сессии/файлы/байты).
- **Выборочное восстановление** сессии части требует кассету этой
  части в приводе; при промахе ошибка подсказывает, какую кассету
  вставить.

Формат данных на ленте — [tape-format.md](tape-format.md).

## Демон и фоновые задачи

`lentovodec daemon` — долгоживущий процесс с REST API, Web UI и реестром
фоновых задач.

- **Одна активная задача**: стример один, параллельные бекапы/
  восстановления невозможны — попытка заканчивается ошибкой «занято»;
  ожидающая кассету задача (`awaiting_tape`) тоже занимает стример.
- **Реестр задач in-memory**: перезапуск демона теряет реестр (но не
  данные — завершённые сессии уже на ленте и в каталоге); активная
  задача при остановке получает до 30 секунд на завершение.
- **Прогресс**: фаза (`scan`/`write`/`finalize`), текущий файл,
  обработано/всего байт, процент, скорость (экспоненциальное
  сглаживание), последние строки лога. CLI/Web UI опрашивают
  `GET /api/tasks/{id}/progress` раз в секунду (WebSocket/SSE нет).
- **Пауза на смену кассеты (spanning)**: когда бекапу/восстановлению
  нужна следующая кассета цепочки, задача переходит в состояние
  `awaiting_tape` и ждёт оператора: Web UI показывает диалог с текстом
  и предложенным именем кассеты, скрипты могут продолжить сами —
  `POST /api/tasks/{id}/continue` с телом `{"tape_name": "..."}`
  (пустое имя — предложенное; допустим и `X-API-Key`). Новая кассета
  бекапа форматируется и регистрируется автоматически; кассета restore
  сверяется по ярлыку и обратной ссылке цепочки. Отдельного
  cancel-эндпоинта нет: отменить ожидающую задачу можно остановкой
  демона — ожидание закрывается сразу, задача завершается ошибкой
  отмены, зафиксированные на лентах части остаются целыми (каталог
  откатывает незавершённый запуск).
- **Устройство**: путь меняется через `POST /api/settings` (при активной
  задаче — 409); лента открывается на время операции, между операциями
  привод свободен.
- **Graceful shutdown**: SIGINT/SIGTERM → остановка HTTP (5 с) → ожидание
  активной задачи (до 30 с).

## Web UI

Пять экранов (бандл Vue 3 встроен в бинарь, раздаётся демоном):

| Экран | Возможности |
|---|---|
| **Login** | Форма логин/пароль; токен сессии — в `localStorage`; показывается вместо всего UI при 401. |
| **Tape** | Информация о текущей кассете, форма форматирования (с `force`), eject, редактор пути устройства. |
| **Jobs** | Карточки заданий с описанием и режимом; запуск (full/inc); форма создания/редактирования; панель прогресса (полоса %, скорость, текущий файл, лог), в состоянии `awaiting_tape` — диалог продолжения со сменой кассеты. |
| **Catalog** | Таблица сессий с фильтром по кассете; удаление. |
| **Files** | Браузер файлов выбранной сессии: хлебные крошки, чекбоксы, выбор каталога (разворачивается в файлы), восстановление в безопасную папку или по оригинальным путям. Tombstone'ы (`D`) невосстановимы — чекбоксов у них нет. |

Русский и английский языки (переключатель, выбор в `localStorage`).
Dev-режим — `make web-dev` (Vite на `:5173`, прокси `/api` на демона).

## Безопасность и сетевой доступ

### Аутентификация демона

| Сценарий | Способ | Кто |
|---|---|---|
| Браузер / CLI daemon-команды | `Authorization: Bearer <session-id>` | Пользователь, залогиненный через `POST /api/auth/login` |
| Скрипты, curl, мониторинг | `X-API-Key: <api_key из TOML>` | Программный доступ |

- Пароль хранится bcrypt-хешем (`lentovodec passwd` генерирует хеш для
  TOML); имя пользователя сравнивается за постоянное время.
- Сессия — случайные 256 бит из `crypto/rand`, живёт в памяти демона с
  TTL (`session_ttl`, по умолчанию 72h) и лимитом 1024; JWT и подписи не
  используются — ревокация всего = перезапуск демона.
- Rate-limit на `/api/auth/login`: 5 попыток / 30 с на IP, затем 429;
  счётчик сбрасывается при успешном входе.
- Аудит-лог: `login_success` / `login_failure` (IP, имя) в общий
  slog-лог с полем `event=auth`; создание задач и форматирование ленты
  логируются с именем пользователя сессии.

### Сетевой доступ

- По умолчанию `bind = 127.0.0.1:29201` — демон из сети не виден;
  удалённое управление — через SSH-туннель (шифрование и аутентификация
  достаются от SSH).
- LAN-доступ — осознанный выбор оператора: не-loopback `bind` без
  настроенного пароля — отказ старта с понятной ошибкой.
- HTTP без TLS — принятый компромисс homelab (токен ходит по вашему
  кабелю/WPA2); нужен TLS — реверс-прокси или SSH-туннель.

### Границы модели (зафиксировано честно)

- Пользователь один, ролей нет.
- Сессии не переживают перезапуск демона (придётся залогиниться заново).
- WebSocket/SSE нет — прогресс только поллингом.

Rootless-модель доступа к стримеру и развёртывание — в
[os-setup.md](os-setup.md).
## Специальные файлы

Поддерживаются символические ссылки, включая dangling symlink, и жёсткие
ссылки: при restore сохраняются соответственно ссылка и общая inode. FIFO,
сокеты, character/block devices, xattr, ACL и filesystem flags не переносятся;
такие записи пропускаются сканером и считаются в `SkippedSpecials`.
